      三段链路：召回 → 规则 → 排序 → 定级

      全链路无外部模型依赖，任意一条结论都可回溯到具体规则
      1. ①

        候选召回

        对 型号+品类+厂商+封装+描述 拼成的文本建 TF-IDF 词向量（jieba 搜索模式分词，无 jieba 时降级为字符 2-gram），用余弦相似度取 top_k = max(4·N, 20) 作为候选池。

      2. ②

        兼容规则过滤

        六维规则逐条判定（类别 / 封装 / 引脚 / 电压 / 功能 / 温度），每条产出 pass warn fail 与中文数值依据；命中零容忍的候选直接落「不推荐」，移出主榜单但保留在排除清单里。

      3. ③

        供应链加权排序

        参数分 param 与供应链因子 supply 合成综合得分，供应链最多影响 ±35%，避免「便宜但装不上」的料冲上榜首。

      4. ④

        风险分级与替代等级

        按停产 / 缺货 / 电压不兼容 / 功能冲突等触发条件判定 🟢低 🟡中 🔴高，并给出四档替代等级与一句话结论。

      核心公式

      与 ranking.py 逐行一致
      参数分 param
      param = 0.70 · rule_score + 0.30 · similarity 型号替换模式
      param = similarity 自然语言需求模式（无原件参数可比）
      供应链因子 supply
      supply = wstock0.45 · wprice0.20 · wlead0.20 · wlife0.15
      缺货（stock ≤ 0）时再乘 0.2 并直接标红；幂次即权重，权重之和为 1。
      综合得分 score
      score = param · ( 0.65 + 0.35 · supply )
      供应链影响力上限 ±35%：supply=1 不倒扣，supply=0 最多打 6.5 折 —— 供货好不会让不合格的料上位，供货差也不至于一票否决。

      六维规则权重

      权重之和 = 1.00
      规则权重判定口径
      类别一致0.20器件品类是否完全相同 零容忍
      封装一致0.15封装字符串是否完全相同 零容忍
      引脚一致0.10脚数差值，0 为 pass，±1~2 为 warn，>2 为 fail 零容忍
      电压兼容0.20候选供电范围是否覆盖原件区间；无交集即 fail 零容忍
      功能一致0.20从描述抽取功能参数指纹（电压/位宽/通道/容量/沟道/Flash/RAM）后等值比对 零容忍
      温度覆盖0.15候选温度区间覆盖原件；不足 80% 记 fail，但不算零容忍
      单项得分：pass = 1.0，warn = 0.5，fail = 0.0； rule_score = Σ 权重 × 单项得分。
      硬约束零容忍（设计决定）

      类别不符 / 封装串不同 / 脚位差 > 2 / 电压零交集 / 功能参数冲突 → 一律「不推荐」，不进主榜单，只在「被规则排除的候选」里给出否决理由。

      温度覆盖不足不算零容忍：温度等级不够是「降额使用 / 需评估环境」，属于工程可评估项，因此按 🟡 中风险 + 规则降权处理，而不是直接判死。这条边界是刻意的 —— 把「装不上」和「用起来要留心」分开。

      供应链四因子口径

      全部归一化到 0–1
      因子权重计算式
      库存 w_stock0.45clamp( log1p(stock) / log1p(10⁶), 0, 1 )，100 万片视为满分
      价格 w_price0.20clamp( 1 − (ratio − 1) × 0.15, 0.6, 1 )，比原型号贵 10% 约扣 1.5%
      交期 w_lead0.20clamp( 1 − (lead − 7) / 60, 0.4, 1 )，7 天为基准，67 天触底
      生命周期 w_life0.15量产 1.00 / NRND 0.75 / 未知 0.70 / 预览 0.60 / EOL 0.15

      风险三级判定

      触发即升级，取最高档
      等级触发条件
      🔴 高风险 EOL 停产 · 库存 ≤ 0 · 电压兼容 fail（供电范围无交集）· 功能一致 fail（关键功能参数冲突）
      🟡 中风险 NRND · 电压兼容 warn（仅部分覆盖）· 封装或引脚不一致（需改板）· 温度覆盖不足 · 类别不同 · 交期 > 30 天
      🟢 低风险 以上均未触发：参数、封装、供电、温度均满足且现货充足，可直接批量替换

      替代等级四档

      按保守程度递进，判定顺序自上而下
      等级判定条件工程含义
      Pin-to-Pin 直接替换 类别 / 封装 / 引脚均 pass，电压非 fail，温度 pass，功能非 fail，且存在引脚兼容证据（人工维护的 p2p_with 关系表，或厂商描述中出现「引脚兼容 / pin-to-pin / 直接替换」等措辞） 不改 PCB、不改固件，可直接换料
      功能等效需改板 封装与引脚一致、但缺少引脚兼容声明，或内核架构 / 引脚定义不同 功能等效，需核对引脚定义，可能需改 PCB 或固件
      参考替代 不满足前两档：功能参数冲突，或封装 / 引脚不一致但未触零容忍 仅供参考，需完整评估外围电路
      不推荐 类别不符 / EOL / 零库存 / 命中任一零容忍硬约束 不做替代方案，仅列入排除清单供核对

      自然语言支路的修正

      TF-IDF 感知不到「品类」与「封装族」
      • 品类归一 + 同义词注入：口语词（如 LDO、DC-DC、单片机）先映射到库中真实品类标签，再把同义词重复 2 次注入查询向量提升 TF 权重；命中品类后做硬过滤，剩余条数即接口里的 filtered_out。
      • 同品类加分 / 封装族降权：同大类但不同脚位的封装（如 SOT-23 vs SOT-23-5）按 0.75 轻降权，跨封装族按 0.65 降权，避免「封装差一位」的候选挤掉精确封装。
      • 接口协议重排：接口芯片是大类（RS-232 / RS-485 / CAN / USB 共用），TF-IDF 分不出协议，按查询中出现的协议关键词重排。
      • 约束只对写明的项出结论：查询里写了电压 / 封装 / 脚位才判定；电压全不覆盖记 fail，封装与脚位不符记 warn（NL 支路没有原件参数，不宜直接判死）。

      作品定位

      • 解决什么问题：缺料 / 停产 / 涨价时，工程师要在几小时内判断「哪颗料能顶上」。本系统把这件事从「翻 datasheet 凭经验」变成「一条可复核的推荐清单」。
      • 差异化在哪：不做黑箱打分。每条推荐都能展开看到六维规则逐条结论 + 中文数值依据 + 供应链四因子取值，落选候选也给出否决理由 —— 可解释性是本作品的核心卖点。
      • 工程形态：纯本地推理，无外部模型 / 无网络依赖，单次查询毫秒级；页面零 CDN 依赖，可离线演示。

      • 本系统输出为工程决策辅助，最终选型须以原厂 datasheet 与实板验证为准 —— 页面里每条结论都给出了可复核的规则依据，就是为了让工程师能快速验证而不是盲信。

      已知局限

      如实列出，不修饰
      1. 自然语言用例仍有 4 条不准：长尾口语表述、多约束叠加（同时指定电压 + 封装 + 功耗）时，召回依赖词面相似度，可能排不出工程上最优的那颗料 —— 这正是需要品类归一与重排补丁的原因。
      2. 供应链因子在现有用例上测不出 Top-1 差异：演示子集规模小、候选区分度主要在规则分上，供应链加权对最终排序名次的影响在评测用例里体现不出来。因此本页只声称「供应链可参与排序」，不声称「供应链提升了 Top-1」。
      3. 规则覆盖依赖描述文本质量：功能一致规则从描述里抽参数指纹，描述缺失参数时只能给 warn（需人工核对），这不是规则失效而是数据不足，页面上会如实显示 warn。
      4. 功能一致不等于参数全集一致：当前指纹覆盖电压 / 位宽 / 通道 / 容量 / 沟道 / Flash / RAM 等可从文本抽取的维度，未覆盖全部电气指标（如精度、噪声、ESR、驱动能力）。
